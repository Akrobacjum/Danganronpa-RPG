3.1 What a flow is: one thing a person at the table does that crosses from one browser to another. It starts on one client (a control or a game.drpg call), is judged or applied on another (the GM's bridge, a socket handler), changes the world or a GM store, and shows on a third (a card, the HUD, a sheet). The suite on one browser cannot see it; the harness can. Rule: every bridge action and every file with a module socket listener belongs to exactly one flow (or to FLOW_EXEMPT with a reason), and every flow names the harness scenarios that drive it end to end, or the stage that will write one. Per-browser features (language, held settings) are not flows.

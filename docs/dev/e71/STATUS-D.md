## How each batch is made

1. A worksheet per slice (key, EN and PL before, the map's screens, the lint's surface and findings, frozen, the early
   pass's rows), generated by a script outside the repository.
2. The English writer (a subagent, fresh context): facts from the code (file and function), the English after, kept,
   removed, needsCode, disagreements - the B01a schema, checked by `batchSchema` (tools/text-render.mjs).
3. The Polish writer (another subagent): a copy of the file with the English afters removed; the Polish from the facts,
   the code and the old Polish (DB26), section 12's steps 1-7.
4. Reviews, each a fresh subagent: EN (with the facts), cold EN (the afters alone), PL in three steps (render and read
   aloud; grammar on the render; order, calques, glossary). No mechanics review: none of B14-B18 is in the plan's list.
5. One revision on the reviews' points; what stays open is the batch file's `reviews`.
6. The afters land in lang/ in place (keys, order and indentation kept); the suite and the scenarios that read the
   changed keys run.

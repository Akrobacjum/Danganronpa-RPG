Model ról jak w BRIEF.md: główny GM = połączony pełny GM o najmniejszym id (utils.mjs `primaryGmId`). Widz = gracz zmarłego
ucznia albo konto Spectatora. Monokuma to postać GM-a: w tej domenie jest tylko kandydatem na karcie do głosowania
(vote.mjs:295-302) i "głosem" Monokuma's Reveal, który naciska GM; nie głosuje.

Jak działa "przez głównego": przycisk drugiego GM-a wysyła prośbę mostem (bridge-guards.mjs:1957-2010, `onPrimary`), główny
wykonuje tę samą funkcję u siebie. Potwierdzenie musi przyjść w `TIMING.ackMs` = 8000 ms (config.mjs:423), odpowiedź w
`TIMING.rulingMs` = 180000 ms (config.mjs:433), chyba że wiersz mówi inaczej. Odmowę na głównym drugi GM widzi jako
`DRPG.Bridge.notDone` "Prośba „{what}” nie została wykonana. {why}" (pl.json:5470), a powód, który nie jest na zamkniętej
liście, jako `why.refused` "Gra na to nie pozwoliła." (pl.json:5511; bridge-guards.mjs:494-498).

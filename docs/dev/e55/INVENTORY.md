# E55 inventory - the CSS consolidation, as the sheets stand at 4dfac3a9

Read-only survey, 12.11.2026, of the repository at `4dfac3a9` (the prep-54 work line = origin/main, 1.2.108).
Nothing in the repository was changed. Every number below was read by a script or a command named next to it; what
could not be proven is said to be unproven, with the reason. Line numbers are at 4dfac3a9 and secondary - the selector
and the file are the name of a target.

How it was read. A small CSS walker (`finders/parse.mjs.txt`: comments stripped, strings and parentheses respected,
`@media`/`@container`/`@supports` descended into, `@keyframes`/`@font-face` kept as leaves) turned the seven served
sheets into 3,776 rules / 11,273 declarations. Cross-check against `node tools/css-lint.mjs`: its `!important` counts
(4 / 0 / 647 / 206 / 0 / 0 / 12) are reproduced exactly; its colour-literal count is reproduced to within one
declaration (352 vs 353 - one in stained-glass.css that sits in a block the walker keeps as a leaf). The sources
grepped as "writers" are `scripts/**/*.mjs` without the `tests*.mjs` files, plus `macros/`; the tests, `audit/`
(harness, glass and style harness pages, captured windows) and `lang/` were grepped separately as second evidence.
There is no `templates/` directory: all markup is built in scripts.

The finder scripts are in `finders/` as `.mjs.txt` (so lint does not read them; run from the repository's root after renaming).

### 2.2 Declarations overridden by a later rule with the identical selector (proven by the cascade's order)

declaration of the same property on the textually identical complex selector under the identical at-rule context;

identical property names are compared (a later shorthand killing a longhand is NOT counted, so this undercounts).

loser); the winners were read and look valid.

## 7. Risks for a consolidation commit series

1. **The freeze has gaps** (1.4): the sheet (one surface), chat cards, the Despair rail, the Event panel, the tray and
   29 listed surfaces are not in the baseline, and the sweep is not in CI. A "pure" move of sheet rules is unmeasured
   unless surface rows (and the `?sheet=parts` stand-in's parts) are added first, or screenshots in both themes are
   compared. Also: only the first element per selector is read, and 33 properties (no margin, no transform, no
   mask, no `::before`) - the brush, the glyph masks, the hope stars and the checkbox tick are `::before`/mask
   properties the snapshot does not read at all.
2. **Order is semantics.** No `@layer`; ties go to the later sheet and the later line. Moving a rule between files
   (or splitting danganronpa.css into new served files) changes its position relative to every equal-specificity rule
   in between; 2.2 shows 73 rule starts where the same selector is stated twice and order decides. A split that adds
   files must keep module.json order equivalent; `tools/css-lint.mjs` reads new sheets automatically, but each new
   file needs a budget row (`--write`), and the stamp `--drpg-css-version` (`verifyStylesheet()`, diagnostics.mjs) lives
   in danganronpa.css and must stay where the release check looks.
3. **Tests read the sheets by name and by text.** danganronpa.css is named in 44 files (157 mentions in tests*),
   stained-glass.css in 25 (84), components.css in 29 (164), narrow.css in 11 (28) - e.g. tests-glyphs.mjs
   `HAND_SHEETS`, tests-tier0.mjs 555, 740, 775, 5271, 13805, 21822-21831, 23579; tests-tier1.mjs 26556. Rules that
   tests cut by text (`lineAround`, regexes on a selector) will fail or, worse, pass vacuously when the text moves. Run
   tiers 0-1 headless (`node run-tests.mjs --tier 1`) after every move commit, and grep the tests for a selector
   before deleting it.
4. **Generated regions.** pixel-icons.css (tools/glyph-map.mjs, tools/glyphs.json) and danganronpa.css 15709-16977
   (tools/chrome-icons.mjs) must be changed through their generators; a hand edit is overwritten at the next run.
   tests-glyphs.mjs, tests-tier0.mjs, tests-tier1.mjs and tools/check.mjs name the generators (what they hold them to
   was not read for this inventory).
5. **`!important` chains.** Many live values are held by an `!important` that answers another `!important` (2.2: the
   strip's colours 94xx, the tray 144xx, the progress bars 9348 -> 14076). Removing the loser is safe; removing a
   winner's `!important` revives whatever it was beating, sometimes a Daggerheart rule this repository cannot see
   (the E44 C6 lines are the declared case). Each lowered budget row should be measured by R1323's cascade and the sweep.
6. **The foreign selectors cannot be proven dead here** (6, 2.6). Deleting a "defensive" rule is a live-table
   decision; v14 markup assumptions are LIVE-unconfirmed (the harness models `ol#chat-log`, Daggerheart's sheet is a
   stand-in). Section 2.5's assumption (`.application.sheet.actor` on every character sheet) is one such.
7. **Theme scoping is asymmetric.** Legacy's values are unscoped and also apply under the glass until overridden; a
   rule moved from "unscoped" to `body:not(.drpg-theme-stained-glass)` gains specificity (0,1,1 more) and can start
   beating glass rules or kit rules (components.css has budget 0 and wins by order; a heavier Legacy rule can take a
   kit property from it under Legacy). The kit's header lists 77 readings already lost to older rules.
8. **Breakpoints**: narrow.css wins by being last and by `#drpg-column` specificity; a consolidated width rule written
   more specifically in a theme would break the stack (code.md's rule: narrow.css loads last). Widths go through tokens
   (`--drpg-events-w`) - keep the token pattern rather than a literal width per theme.
9. **Contrast and floor**: `node tools/check.mjs contrast` and the floor test (`FLOOR_SURFACES`) read tokens per
   theme; merging near-miss colours (5) changes measured ratios - each merged pair needs its row in
   tools/contrast-pairs.json re-read.
10. **The budget ratchet is two-sided**: every commit that removes an `!important` or a literal must lower
    tools/css-budget.json in the same commit (`node tools/css-lint.mjs --write`), or `check css` goes red.

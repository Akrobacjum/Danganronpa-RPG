## 3. Boundary with E25 and E57

E71 changes UI keys and config prose only, never the handbooks. A key E25 fixed and recorded by the guide is checked,
not rewritten (O12), unless the lint or a reviewer finds a fault; then the change is the batch's and E25's record is
updated in the same commit. A fact error E71 finds (code against text) is written in the batch's `disagreements`, and the
text is made true; if code is wrong, it goes to the owner, not changed here. Handbook halves of S08-49, S09-43, S11-52,
S13-34 and every handbook sentence that names a renamed button are E57's, which starts from E71's finished UI.

## 7. Risks

- Lost mechanics when shortening: facts before text, the "facts kept" column, the mechanics review (audit's risk).
- Natural but mirrored Polish: T22 below 70% is a signal, not proof.
- Overflow after length changes: T4, a warning at PL over 140% of EN, screenshots after each window batch.
- Scale: about 1100-1400 EN strings edited in full plus as many PL (the audit's estimate); one batch per commit so one
  red batch does not hold the rest.
- Earlier stages' own tests (for example for S13-06, S10-68) must stay green: a batch changes text only.
- Item table labels changed without an alias lose a GM's tables (T14, LEGACY_PLURALS, LEGACY_GOAL_LABELS).

## 1. Goal

The owner's audit entry for E99 (`goal`, translated from Polish):

> At the trial, always the graph, never the list alone. From the trial console the GM opens "Case schema" (GM only), with
> a box to tick on every conclusion, counter and solution, with hints after presentations (the module only hints, the GM
> decides) and with the minigames' buttons. The list of modes reads the same table of modes the trial uses, and a census
> test holds that every mode has a name and a start button in the schema (known from E73: Straw Poll, Logic Dive, Scrum
> Debate). After the verdict the players get a summary on an animated board, like the verdict board: only what was
> discovered (no undiscovered Remnants, Truth Bullets or conclusions), and the solution only when the class voted right.
> The GM composes the summary and sends only what was discovered. Open question D2, with a default answer: the GM
> presses "Show summary" after the verdict and the board plays for everyone (the other option: it starts by itself, right
> after the verdict board).

Done when (`doneWhen`, translated): the GM runs the trial on the schema with ticking and minigame buttons, the census of
modes is green, and after the verdict the players get a summary with only what they discovered.

Verify (`verify`, translated): a census test of modes (every mode of the trial's table has a button in the schema); a test
that the summary on a player's browser holds nothing undiscovered, and with a wrong vote no solution; a trial scenario on
four clients with ticking and the board; screenshots of the board in both themes and both languages; at the table, a
trial run on the schema (a LIVE check).

Risk (`risk`, translated, in short): the summary carries only what was discovered, because the GM composes it and the
player's browser never receives the rest; a stage that adds a trial mode and forgets the schema fails the census; the board
needs a static version under reduced motion, as E61's boards; after E99 the two-digit stage ids run out.

The audit's own forecast: `effort` "to be estimated after the mockup round (a large stage)"; the schedule of 10.11 and
11.11 (data.json `plan.schedule`) prices E99 at 3.5-5 units "by likeness, without mockups" (between E61 3-4 and E94 4-5),
and the 11.11 recount uses a middle of 2.1 h a unit.

## 6. Risks

- **The dependencies are not built.** E97, E98 and E61 are all ahead of E99 and none is in the tree. Every file and
  function of theirs named above is a name from their entries; C3-C7 will be re-read against their real code at C0.
- **A leak by composition.** The payload is built on a GM's browser from GM stores; one wrong field is enough. The
  allowlist in C6, the world-secrets rule in C7 and 72-canary's new phase are three readings of the same promise.
- **The console's cost.** A schema redrawn with the live region each second would show in 86-frame-work's counters.
- **E73's rebuild.** E73 (1.2.115) rebuilds the console's middle; C5's frame must leave it a slot, and the census must
  read the table E73 will add rows to.
- **A second trial in a chapter.** The trial record already distinguishes trial and chapter fields (`TRIAL_RECORD`
  `lives`); the ticks and `summaryShown` must be the trial's.
- **The name "summary".** Taken by the day summary; a key or a notice source reused by mistake would mix them in E81's
  history.

## 3. Boundary with E71 and E57 (one key changes once)

| Text | E25 | E71 | E57 |

| Handbook form, length, appendix, PL from facts | not touched | - | does |

The one place a key could still be edited twice is a UI key E25 fixes that E71's batch would also restyle. The proposal
(Q-E25-1) closes it: E25 writes each changed key in the B01a schema (`docs/dev/text-batch-B01a.json`, held by
`tools/text-render.mjs batchSchema`), so E71 treats it as a text written by the guide.
